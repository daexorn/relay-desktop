# Relay

Версия 0.12.0 открывает `/login` в браузере **на выбранном сервере**. Relay получает
его изображение по SSH и возвращает клики, прокрутку и ввод с клавиатуры. Страницы
Claude, провайдера входа и callback загружаются серверным Chromium; cookies и профиль
остаются на сервере. На компьютере работает только просмотр изображения и управление.
После подтверждения входа можно продолжить прежний разговор; задания автоматически
не повторяются. Если Claude показал код, его можно подтвердить отдельным полем Relay.

Кнопка **Браузер** под выбранным подключением открывает обычный браузер сервера,
без запуска входа или сессии Claude. Есть адресная строка, вкладки, переходы назад/вперёд,
обновление страницы, прокрутка, клавиатура и копирование выделения. Адреса без протокола
открываются через HTTPS. Закрытие окна или SSH-соединения завершает браузер, а его профиль
остаётся на том же сервере. Одновременно для аккаунта открывается одно окно браузера.

Для сервера Debian/Ubuntu кнопка **Подготовить браузер на сервере** устанавливает
Chromium, его sandbox, Xvfb и отдельного системного пользователя `relay-browser`.
Для установки нужны права root. Браузер работает от отдельного пользователя, с приватным
профилем и закрытым X11-экраном. Управление Chromium идёт через наследуемые FD,
без открытого отладочного TCP-порта. Для потока оставляется один неподтверждённый кадр
и последний ожидающий; изображение не записывается в историю или журнал.

Claude Code сам сохраняет и обновляет свой вход. Relay не копирует файлы авторизации
между хостами и не продлевает отозванные токены. Это удобный способ заново войти,
а не исправление пока не установленной причины ежедневного `/login`.

Версия 0.10.1 исправляет ошибку `unexpected keyword argument 'revoke'` при работе
API-сессий с подключённым ПК: смена режима и закрытие сессии больше не прерывают очистку
соединения. Остановка ответа сохраняет подключение, закрытие отзывает его только для этой сессии.

Relay поддерживает собственный OpenAI-совместимый API-агент. Для каждого SSH-сервера можно
указать отдельные URL, ключ и модель, а в существующем разговоре переключаться между
Claude Code и API. История и идентификатор сессии сохраняются. API-режим сам обращается
к провайдеру с выбранного сервера и использует инструменты Relay; Claude Code для него
не нужен. На серверах достаточно Python 3.9+.

Кнопка **API** рядом с названием Relay открывает настройки выбранного сервера.
Укажи базовый URL (для Tooken: `https://tooken.club/v1`), ключ и ID модели. Кнопка проверки
загружает каталог моделей с этого сервера. Внизу чата источник **Claude Code / API**
выбирается отдельно для каждого разговора; настройка сервера задаёт начальное значение.
Модель, режим подтверждений и effort доступны рядом. Лимиты ответа и числа шагов
задаются в настройках API.

API-агент поддерживает потоковый текст, картинки, прикреплённые файлы, команды сервера,
чтение/запись/редактирование файлов, поиск, общую доску и инструменты подключённого ПК.
Кластеры используют API-профиль соответствующего хоста для руководителя и работников;
можно смешивать API и Claude Code на разных узлах. Подтверждения и режим планирования
сохраняются. Остановка прерывает команду; запросы и уже исполненные действия автоматически
не повторяются. Прерванный текст и результаты инструментов остаются в истории.

Ключи находятся отдельно от экспортируемых настроек: `api-keys.json` в каталоге Relay,
с правами 0600 на Linux. При работе ключ передаётся по SSH выбранному серверу и хранится
в памяти API-движка; в историю разговоров и серверные конфиги он не записывается.
API-режим не использует подписку и OAuth Claude Code: запросы оплачиваются у выбранного
API-провайдера. API доступен в Windows/Linux и Android; на Android ключ хранится
в зашифрованном хранилище с Android Keystore и вводится отдельно на телефоне.

Сохранены папки, закрепление и переименование сессий — общие для всех, кто
подключается к серверу; 13 цветовых тем, у каждой свой акцент; плавное появление
сообщений; полный набор эмодзи (Noto Emoji); формулы в окружениях `equation`,
`align`, `gather` и других без `$`; в истории больше нет служебных строк Claude Code,
а картинки видны в сообщениях.

**Relay для Android** (папка `android/`, Kotlin и Jetpack Compose): те же 13 тем, сессии
с закреплением и общими папками, история, ответы с формулами LaTeX (Markwon и JLatexMath,
кириллица внутри формул), сворачиваемые действия и вывод команд, разрешения, выбор модели,
режима и глубины. Версия Android 0.3.1 поддерживает собственный API: кнопка **API**
у каждого сервера открывает настройки, а источник выбирается внизу чата.
Подключается по SSH и запускает на сервере тот же помощник, что
десктопный Relay. Сборка: `cd android && ./gradlew assembleRelease`; тесты:
`./gradlew testDebugUnitTest` (протокол с настоящим помощником, формулы, скриншоты экранов
в `app/build/screens`).

Формулы LaTeX работают в сообщениях и результатах команд: дроби,
матрицы, интегралы и кириллица внутри формул. Поддерживаются формулы в строке,
отдельные блоки, списки и таблицы; исходник можно скопировать правой кнопкой.

Доступны удаление сессий и передача до восьми вложений общим размером 512 МБ
с прогрессом, отменой и восстановлением черновика при обрыве связи.

Управляемый агентский кластер — отдельная сессия Claude-руководителя,
который назначает работу исполнителям, получает результаты и раздаёт доработки.
У сессии есть заметная метка, схема команды, журнал и сохраняемая история.

## Команда с руководителем

1. Сохраните и подключите SSH-хосты обычным способом.
2. Откройте **Агентский кластер → Новая команда**. Выберите хост руководителя и добавьте
   исполнителей. Для каждого доступны имя, хост, рабочая папка, модель и глубина размышлений.
   Несколько агентов могут работать на одном хосте; можно использовать разные хосты и учётные записи.
3. В **Промптах** задайте общие инструкции, отдельный промпт руководителя и промпты исполнителей.
   В **Лимитах** выберите режим разрешений, параллелизм и общее число назначений.
4. Опишите цель команды и запустите сессию. Руководитель сам использует инструменты назначения,
   ожидания, получения результатов и отмены. Исполнители отвечают руководителю; уточнения от
   пользователя отправляются в его сессию.
5. На схеме видны реальные состояния: очередь, работа, ожидание подтверждения, готовый результат,
   ошибка или остановка. Карточки открывают разговор нужного агента.

У каждого исполнителя своя продолжаемая Claude-сессия внутри кластера. Повторные поручения
сохраняют его контекст. Один исполнитель получает по одной задаче, общий параллелизм ограничивает
Relay. Зависимости между назначениями позволяют дождаться изменений перед проверкой.
Результаты возвращаются через инструменты руководителя; если он закончил ответ раньше работников,
Relay передаёт ему готовые результаты следующим сообщением. Черновик пользователя сохраняется.

Настройки и промпты сохраняются со сессией. Изменения инструкций применяются после текущей работы;
смена хоста или папки руководителя требует новой сессии. На каждом хосте нужна подготовленная
рабочая копия проекта: наличие одних и тех же файлов на разных хостах не подразумевается.

Кластер работает, пока Relay открыт. После закрытия сессии остаются на серверах, история команды
сохраняется на ПК. При следующем запуске кластер открывается на паузе, прерванные задачи отмечены
явно и автоматически не повторяются. **Пауза очереди** задерживает новые назначения;
**Остановить команду** останавливает руководителя и исполнителей.

## Ключи и текстовые вставки

Под редактором промпта есть **Вставить ключ**, а во вкладке **Вставки** — полный список.
Имена серверов берутся из сохранённых подключений Relay слева. Если профиль называется Production:

- `[данные_айпи_(Production)]` — его адрес или домен;
- `[данные_порта_(Production)]` — SSH-порт;
- `[данные_пользователя_(Production)]` — пользователь;
- `[данные_папки_(Production)]` — рабочая папка профиля;
- `[данные_сервера_(Production)]` — имя, адрес, порт, пользователь и папка вместе.

Также доступны `[имя_кластера]`, `[имя_агента]`, `[рабочая_папка]`, `[хост]`, `[задача]`
и `[дата]`. Контекстные ключи заполняются для конкретного агента. Предпросмотр показывает
готовый текст подстановки. При одинаковых именах профилей список предлагает отдельные ключи.

В **Мои фрагменты промпта** можно создать собственный ключ, например `[контекст_проекта]`,
и сохранить за ним инструкции. Внутри фрагмента тоже работают данные серверов и другие вставки.
Циклы, неоднозначные профили и неизвестные данные серверов показываются как ошибка до отправки.

## Оформление и очередь сообщений

Сохранены пять тем (Графит, Полночь, Хвоя, Слива, Бумага), масштаб, ширина чата, компактные
отступы, анимации и выбор Enter/Ctrl+Enter. Команды показываются карточками с отдельным выводом,
кодом завершения при наличии, выделением ошибок и копированием. Ответы команды отображаются
с именем исполнителя, состоянием и оформленным результатом.

Во время ответа кнопка отправки добавляет сообщение с файлами в **очередь**. Следующие сообщения
отправляются по порядку после ответа. Доступны изменение, удаление и пауза. Очередь неотправленных
сообщений хранится в открытом приложении; при закрытии Relay предупреждает о незавершённой работе.

Нативное приложение для Claude Code на ваших серверах. Windows и Linux,
без ручного входа в терминал; окно серверного браузера открывается для авторизации.

## Начать работу

**Windows:** распакуйте архив и откройте `Relay.exe`. Дополнительно устанавливать
Rust, Python или SSH-клиент на компьютере не нужно. Поддерживаются Windows 10/11 x64.
Сборка пока не подписана, поэтому Windows может показать проверку издателя.

**Linux:** распакуйте архив и откройте `relay` или запустите `./relay` в папке.
`./install.sh` добавляет Relay в меню приложений. Сборка x64 требует glibc 2.39+
(например, Ubuntu 24.04 или современный Void/Arch/Debian), OpenGL 2.0+ и libdbus-1.
Для выбора файлов через диалог нужен работающий XDG Desktop Portal. Перетаскивание
файлов и буфер изображений доступны независимо от диалога.
Браузер установлен на сервере; для просмотра трансляции на ПК WebKit/WebView2 не нужен.

1. Нажмите **+** слева и укажите имя, IP или домен, SSH-порт, пользователя и пароль.
2. При первом подключении подтвердите ключ сервера. Изменившийся ключ не принимается автоматически.
3. Выберите рабочую папку. Откройте существующий разговор или нажмите **Новая сессия**.
4. Напишите задачу. **Enter** отправляет, **Shift+Enter** добавляет строку, **Ctrl+N** создаёт сессию.

На сервере Linux нужен Python 3.9+. Для режима Claude Code нужен авторизованный Claude Code
у выбранного пользователя (проверено с 2.1.325); API-режим использует отдельный ключ
выбранного провайдера. Приложение не устанавливает системный сервис,
не открывает сетевой порт и не меняет настройки Claude.

## Сессии и рабочие папки

Панель слева показывает реальные сохранённые сессии Claude, включая разговоры,
созданные в терминале. Можно искать по названию, смотреть все папки или только
текущую. Кнопка папки открывает серверный каталог; последние папки сохраняются.
После перезапуска остаются серверы, выбранная папка и последний разговор.

Продолжение запускается через `claude --resume=<session-id>`, без создания копии.
История и новые сообщения остаются в обычных сессиях Claude на сервере. Relay
не переписывает существующие JSONL-файлы. Показана последняя ветка разговора;
для очень длинных сессий загружается ограниченный фрагмент истории. Повреждённые
строки пропускаются; старые записи без UUID также читаются. При задержке начальной
загрузки выполняется до трёх повторов. Кнопка обновления запускает новую попытку.
Когда фильтр папки скрывает все сессии, можно показать сессии из всех папок.

После повторного входа в Claude на сервере Relay перед следующим сообщением обновляет
простаивающий процесс и продолжает тот же разговор. Обычные процессы без фоновых задач
освобождаются после 15 минут простоя; история остаётся на сервере. Получение списка моделей
не запускает дополнительный Claude одновременно с открытым разговором.

При ошибке авторизации очередь ставится на паузу. Уже отправленные задания автоматически
не повторяются. Если Claude требует повторный вход, используйте `/login` в Relay для нужного сервера,
затем отправьте следующее сообщение в прежнюю сессию. Relay не восстанавливает отозванные
токены и не изменяет файл входа Claude.

Переключение серверов не останавливает работу в других открытых разговорах.
При закрытии приложения с активной задачей есть подтверждение: задача остановится,
историю можно будет продолжить. После потери сети сообщение не отправляется повторно
автоматически. Подключитесь снова, чтобы прочитать сохранённое и продолжить.

## Общая доска задач

Доска доступна в приложении и серверному помощнику. Люди и агенты работают с одним
состоянием: задачи, исполнители, статусы, оценки, частичная готовность и журнал
изменений. Категории можно создавать, переименовывать, окрашивать и перемещать
по холсту; задачи можно связывать и переносить между категориями.

В исходники также включён экспериментальный модуль игровых проверок. Он запускается
отдельным действием и создаёт собственную копию Minecraft + Fabric. Обычный запуск
Relay игру не открывает. В этом выпуске проверены протокол передачи, обработка
сценариев и сборка; сквозные проверки с запуском Minecraft не выполнялись.

## Прикрепить файлы

Кнопка **Прикрепить файлы** выбирает любые файлы. Можно перетащить их в окно.
**Ctrl+V** вставляет изображение из буфера, обычный текст вставляется в поле задачи.
У каждого вложения есть карточка с именем, размером и удалением; у изображения — миниатюра.

До восьми вложений, суммарно **512 МБ**. Большие файлы передаются частями с
индикатором прогресса и проверкой SHA-256; целиком в память Relay они не загружаются.
Передачу можно остановить. При обрыве или отмене текст и вложения возвращаются
в черновик, а если уже набран новый текст — в начало очереди на паузе.

PNG, JPEG, WebP и GIF (первый кадр)
отправляются прямо в сообщение: изображение уменьшается до 1800 px и максимум 4 МБ.
Изображения в одном сообщении — до 16 МБ после уменьшения. Исходные изображения
больше 24 МБ отправляются обычными файлами без перекодирования.
Документы, код, архивы и другие файлы передаются по SSH в личный каталог
`~/.cache/relay-desktop/attachments/<сессия>/` на сервере. Рабочие файлы проекта
не заменяются. Claude получает путь, чтобы прочитать вложение обычным инструментом.

Файлы остаются доступны для продолжения сессии. Relay не использует внешний хостинг.
В восстановленной истории показываются имена, а не служебные пути. Сами изображения
сохраняет Claude и учитывает при продолжении разговора.

## Удалить историю сессии

Нажми корзину справа от сессии или выбери **Удалить сессию** правой кнопкой мыши.
Relay покажет название и запросит подтверждение. Из списка сессия исчезает после
подтверждения сервера; файлы проекта и другие разговоры не меняются.
Во время ответа сначала нужно нажать «Стоп»; для занятого кластера — остановить команду.
Черновик и очередь удаляемой сессии тоже удаляются.

Запись Claude и её подчинённые сессии перемещаются из активной истории в скрытый
резервный каталог `.relay-deleted` внутри соответствующего каталога проекта Claude.
Обычный `--resume` эту копию больше не видит. При продолжении завершённой команды
кластера Relay использует новую сессию с прежними настройками и промптами.

## Скачать готовый файл

Если Claude прислал путь к собранному моду, архиву или документу, под ответом
появляется карточка **Скачать**. Нажатие на ссылку файла в сообщении работает
так же. Файл передаётся с выбранного сервера по SSH в папку **Загрузки** на ПК;
включать **Подключить ПК** и разрешать выполнение команд для этого не требуется.
Обычные ссылки на сайты по-прежнему открываются в браузере.

Можно написать: «Собери мод и дай ссылку на готовый jar». Claude получает указание
проверить файл и показать полный серверный путь. В старых сообщениях поддерживаются
также пути в обратных кавычках и имена файлов в стандартных каталогах сборки.
Если файл не существует, карточка показывает ошибку; она не означает, что сборка
уже завершена. Скачивание само по себе не устанавливает мод в инстанс.

Размер — до 512 МБ. Relay проверяет размер и SHA-256 перед сохранением. Статус
«Файл сохранён» появляется после проверки; полный локальный путь виден при наведении.
Для передачи нужны открытое приложение и подключение к серверу.

## Этот компьютер: файлы и команды

Над полем сообщения нажмите **Подключить ПК**. Выбор папки не требуется: стартовый
каталог команд — домашняя папка. Это полный доступ с правами пользователя Relay;
каталог запуска не ограничивает доступ к другим папкам компьютера. Состояние
показано на кнопке: **Этот ПК · Авто** или **Этот ПК · Вручную**. Повторное нажатие
или крестик отключает ПК. Старые профили после обновления требуют подключения ПК
заново, поэтому автоматическое выполнение не включается незаметно.

Общий переключатель режима под сообщением действует и на локальные инструменты:

- **Авто:** команды на ПК выполняются без отдельных подтверждений. Файлы
  сохраняются автоматически: по пути `destination`, который указал Claude,
  или в папку загрузок, если путь не указан. Допускаются абсолютные пути
  в другие каталоги ПК и пути относительно стартовой папки.
- **С подтверждением / Правки файлов / План:** локальное действие показывает
  отдельный запрос; место сохранения файла выбирается через системный диалог.

Claude получает два настоящих MCP-инструмента. Дополнительная инструкция сообщает
ОС, каталог запуска и режим; выполнение делает код Relay через существующее SSH-
соединение. У модели нет прямого соединения с ПК или отдельного пароля от него.

Скачивание — до 512 МБ, частями по SSH, со сверкой размера и SHA-256. До окончания
проверки файл хранится отдельно. При замене прежний обычный файл сохраняется рядом
под скрытым именем `.relay-backup-*`; каталоги и специальные файлы не заменяются.
Windows использует PowerShell, Linux — `/bin/sh`. Claude получает stdout, stderr и
код завершения; до 120 секунд на команду, 16 КиБ вывода на каждый поток с отметкой
о сокращении. Фоновая программа может продолжить работу после команды запуска.

Остановка задачи отменяет ожидающие локальные действия и активную команду.
Разрешение Авто проверяется на самом ПК для конкретной беседы; поле `auto` в ответе
сервера само по себе ничего не разрешает. При отключении ПК локальные политики
сбрасываются. Повышение прав пользователя автоматически не выполняется.

Например: «Скачай собранный jar в мой инстанс» или «Проверь локальный latest.log».
Автоматизация Minecraft зависит от установленного лаунчера и средств управления;
Relay не содержит готового игрового бота и не запускает игру самостоятельно.

На сервере создаётся временный MCP-помощник и приватный Unix-сокет в каталоге 0700.
Они работают в рамках SSH-подключения, без новых TCP-портов и постоянного сервиса.
Используется [MCP в Claude Code](https://code.claude.com/docs/en/mcp).

## Журнал действий

Последовательные чтения, команды и их результаты свёрнуты в строку вида
**12 действий · Показать**. В журнале остаются короткие названия файлов; полные
параметры и результаты открываются при выборе действия. Ошибки видны в свёрнутом
заголовке. Текст разговора, вопросы и запросы разрешений остаются на виду.

## Режимы работы

- **Авто:** встроенный автоматический режим Claude Code, без отключения системы разрешений. Выбран по умолчанию; последняя настройка сохраняется для сервера.
- **С подтверждением:** запросы разрешений Claude появляются в чате с кнопками.
- **Правки без запроса:** обычные изменения файлов разрешены; остальные запросы
  Claude по-прежнему показываются.
- **Планирование:** Claude изучает задачу и готовит план.

**Effort**: авто, low, medium, high, xhigh и max. Настройка сохраняется для сервера;
доступность уровней зависит от модели и версии Claude Code.

Изменение режима, модели или Effort применяется при следующем сообщении. Поддерживаются
модель сервера по умолчанию, Sonnet и Opus. **Стоп** прерывает текущий ответ.
Вопросы Claude поддерживают варианты, несколько вариантов и свободный ответ.
Relay не добавляет `--dangerously-skip-permissions`.

## Лимиты Claude

В нижней части панели сервера показаны шкалы использования за **5 часов** и
**неделю**, проценты и время до сброса. Данные обновляются при подключении,
затем не чаще раза в минуту и по событиям Claude Code. На сервере используется
уже имеющаяся действующая авторизация подписки. Серверный помощник читает OAuth-
токен из конфигурации Claude для запроса статистики; на ПК токен не передаётся.

Дополнительный источник лимитов — фиксированный endpoint самого Claude Code.
Его HTTP-контракт не является публичным и может меняться. При недоступности
используются официальные события `rate_limit_event`; если и они не содержат
проценты, интерфейс явно показывает отсутствие данных, без расчётов по числу токенов.
Relay не обновляет авторизацию и не запускает задачу Claude для проверки лимитов.

## Данные и пароли

Профили: `%APPDATA%\relay-desktop\settings.json` на Windows,
`$XDG_CONFIG_HOME/relay-desktop/settings.json` или `~/.config/relay-desktop/settings.json`
на Linux. В JSON нет паролей или локальных копий разговоров.

По флажку **Запомнить пароль** используется Windows Credential Manager или
Secret Service на Linux (GNOME Keyring, KeePassXC с Secret Service и т. п.).
Если хранилище недоступно, Relay сообщает об этом и позволяет подключиться без
записи пароля на диск. Пароли не кладутся в командную строку или журнал приложения.
Приложение не собирает телеметрию.

## Формулы

Ответы могут содержать формулы LaTeX: `$...$` в строке и `$$...$$` отдельным блоком,
а также `\(...\)` и `\[...\]`. Их рисует сам Relay с помощью RaTeX, совместимого
с KaTeX движка на Rust, без браузера и подключения к сети. Кириллицу внутри `\text{...}`
набирает встроенный шрифт Computer Modern Unicode. Формулы работают в абзацах, списках,
цитатах и таблицах, а широкая формула прокручивается вбок.

Правый клик по формуле предлагает **Скопировать LaTeX**. Обычные знаки `$` (цены,
переменные shell) и код остаются как есть. Формула с ошибкой показывается исходником,
а причина ошибки видна в подсказке. Агенты узнают о поддержке формул из системного
промпта Relay, поэтому пишут их в LaTeX сами.

## Сборка и проверки

Исходники — Rust 1.98, egui/eframe, russh, Python stdlib для серверного помощника.
На Windows для сборки нужны Rust MSVC и Microsoft C++ Build Tools.
На Linux — Rust, C-компилятор, pkg-config и заголовки libdbus-1.

```sh
cargo build --release --locked
cargo test --locked
cargo test --locked -p egui_commonmark --lib relay_list_layout_tests
python3 -m unittest discover -s tests -v
python3 tools/package.py
```

`tools/build-windows-local.sh` — дополнительный вариант кросс-сборки с Linux:
требует подготовленных официальных Rust и llvm-mingw внутри `.tools/`.
Обычная сборка на Windows не требует этих скриптов. Workflow в `.github/workflows/`
собирает обе платформы на собственных runner-ах без публикации релиза.

Названия сессий берутся из содержательных сообщений. Строки `--resume`, `/resume`
и другие служебные команды не используются в заголовках. Оригинальные сессии не удаляются.

`relay --demo` — автономный предпросмотр с вымышленными данными. К реальным
серверам он не подключается. `--screenshot <path>` сохраняет только окно Relay.

Протокол и флаги сверены с [документацией Claude Code](https://code.claude.com/docs/en/cli-reference)
и [официальным Agent SDK](https://github.com/anthropics/claude-agent-sdk-python).
Это независимое приложение, не официальный продукт Anthropic.

## Проверка интерфейса

`python3 tools/preview.py` сохраняет реальные снимки чата, подключения, пустого чата
и светлой темы. `tools/check-paste.py` проверяет фактический Ctrl+V в отдельном
демоокне с восстановлением буфера; не затрагивает рабочие сессии.
Шрифт Inter распространяется по OFL, лицензия — `assets/Inter-LICENSE.txt`.
Локальные изменения `vendor/egui_commonmark` и `vendor/egui_commonmark_backend`
исправляют выравнивание списков и интервалы в тексте.
`vendor/egui-winit` содержит небольшой фикс передачи события Ctrl+V: стандартная
интеграция перехватывала его даже при отсутствии текста в буфере.
Те же `vendor/egui_commonmark*` выводят формулы в таблицах и раздвигают строки текста
вокруг высоких формул. `vendor/ratex-unicode-font` принимает встроенный шрифт вместо
поиска системного, а `vendor/ratex-layout` учитывает реальные ширины кириллических букв.
`--demo-math` и `--demo-math-2` показывают формулы в демоокне. Шрифт Computer Modern
Unicode распространяется по OFL, лицензия — `assets/CMU-LICENSE.txt`.
