# Relay

Версия 0.5.0 объединяет серверную ветку redesign с опубликованным Relay: новый
интерфейс, исправление повторяющихся ответов, сессии из всех папок и общая доска
задач с категориями на свободном холсте. Скачивание файлов из чата и управление
подключённым ПК сохранены.

Нативное приложение для Claude Code на ваших серверах. Windows и Linux, без
встроенного браузера и без ручного входа в терминал.

## Начать работу

**Windows:** распакуйте архив и откройте `Relay.exe`. Дополнительно устанавливать
Rust, Python или SSH-клиент на компьютере не нужно. Поддерживаются Windows 10/11 x64.
Сборка пока не подписана, поэтому Windows может показать проверку издателя.

**Linux:** распакуйте архив и откройте `relay` или запустите `./relay` в папке.
`./install.sh` добавляет Relay в меню приложений. Сборка x64 требует glibc 2.39+
(например, Ubuntu 24.04 или современный Void/Arch/Debian), OpenGL 2.0+ и libdbus-1.
Для выбора файлов через диалог нужен работающий XDG Desktop Portal. Перетаскивание
файлов и буфер изображений доступны независимо от диалога.

1. Нажмите **+** слева и укажите имя, IP или домен, SSH-порт, пользователя и пароль.
2. При первом подключении подтвердите ключ сервера. Изменившийся ключ не принимается автоматически.
3. Выберите рабочую папку. Откройте существующий разговор или нажмите **Новая сессия**.
4. Напишите задачу. **Enter** отправляет, **Shift+Enter** добавляет строку, **Ctrl+N** создаёт сессию.

На сервере Linux нужны Python 3.9+ и авторизованный Claude Code у выбранного пользователя.
Проверено с Claude Code 2.1.303. Отдельного API-ключа Relay не требует: используется
уже настроенная авторизация Claude на сервере. Приложение не устанавливает сервис,
не открывает сетевой порт и не меняет настройки Claude.

## Сессии и рабочие папки

Панель слева показывает реальные сохранённые сессии Claude, включая разговоры,
созданные в терминале. Можно искать по названию, смотреть все папки или только
текущую. Кнопка папки открывает серверный каталог; последние папки сохраняются.
После перезапуска остаются серверы, выбранная папка и последний разговор.

Продолжение запускается через `claude --resume=<session-id>`, без создания копии.
История и новые сообщения остаются в обычных сессиях Claude на сервере. Relay
не переписывает существующие JSONL-файлы. Показана последняя ветка разговора;
для очень длинных сессий загружается ограниченный фрагмент истории. Повреждённые
строки пропускаются; старые записи без UUID также читаются. При задержке начальной
загрузки выполняется до трёх повторов. Кнопка обновления запускает новую попытку.
Когда фильтр папки скрывает все сессии, можно показать сессии из всех папок.

Переключение серверов не останавливает работу в других открытых разговорах.
При закрытии приложения с активной задачей есть подтверждение: задача остановится,
историю можно будет продолжить. После потери сети сообщение не отправляется повторно
автоматически. Подключитесь снова, чтобы прочитать сохранённое и продолжить.

## Общая доска задач

Доска доступна в приложении и серверному помощнику. Люди и агенты работают с одним
состоянием: задачи, исполнители, статусы, оценки, частичная готовность и журнал
изменений. Категории можно создавать, переименовывать, окрашивать и перемещать
по холсту; задачи можно связывать и переносить между категориями.

В исходники также включён экспериментальный модуль игровых проверок. Он запускается
отдельным действием и создаёт собственную копию Minecraft + Fabric. Обычный запуск
Relay игру не открывает. В этом выпуске проверены протокол передачи, обработка
сценариев и сборка; сквозные проверки с запуском Minecraft не выполнялись.

## Прикрепить файлы

Кнопка **Прикрепить файлы** выбирает любые файлы. Можно перетащить их в окно.
**Ctrl+V** вставляет изображение из буфера, обычный текст вставляется в поле задачи.
У каждого вложения есть карточка с именем, размером и удалением; у изображения — миниатюра.

До восьми вложений, суммарно 12 МБ. PNG, JPEG, WebP и GIF (первый кадр)
отправляются прямо в сообщение: изображение уменьшается до 1800 px и максимум 4 МБ.
Документы, код, архивы и другие файлы передаются по SSH в личный каталог
`~/.cache/relay-desktop/attachments/<сессия>/` на сервере. Рабочие файлы проекта
не заменяются. Claude получает путь, чтобы прочитать вложение обычным инструментом.

Файлы остаются доступны для продолжения сессии. Relay не использует внешний хостинг.
В восстановленной истории показываются имена, а не служебные пути. Сами изображения
сохраняет Claude и учитывает при продолжении разговора.

## Скачать готовый файл

Если Claude прислал путь к собранному моду, архиву или документу, под ответом
появляется карточка **Скачать**. Нажатие на ссылку файла в сообщении работает
так же. Файл передаётся с выбранного сервера по SSH в папку **Загрузки** на ПК;
включать **Подключить ПК** и разрешать выполнение команд для этого не требуется.
Обычные ссылки на сайты по-прежнему открываются в браузере.

Можно написать: «Собери мод и дай ссылку на готовый jar». Claude получает указание
проверить файл и показать полный серверный путь. В старых сообщениях поддерживаются
также пути в обратных кавычках и имена файлов в стандартных каталогах сборки.
Если файл не существует, карточка показывает ошибку; она не означает, что сборка
уже завершена. Скачивание само по себе не устанавливает мод в инстанс.

Размер — до 512 МБ. Relay проверяет размер и SHA-256 перед сохранением. Статус
«Файл сохранён» появляется после проверки; полный локальный путь виден при наведении.
Для передачи нужны открытое приложение и подключение к серверу.

## Этот компьютер: файлы и команды

Над полем сообщения нажмите **Подключить ПК**. Выбор папки не требуется: стартовый
каталог команд — домашняя папка. Это полный доступ с правами пользователя Relay;
каталог запуска не ограничивает доступ к другим папкам компьютера. Состояние
показано на кнопке: **Этот ПК · Авто** или **Этот ПК · Вручную**. Повторное нажатие
или крестик отключает ПК. Старые профили после обновления требуют подключения ПК
заново, поэтому автоматическое выполнение не включается незаметно.

Общий переключатель режима под сообщением действует и на локальные инструменты:

- **Авто:** команды на ПК выполняются без отдельных подтверждений. Файлы
  сохраняются автоматически: по пути `destination`, который указал Claude,
  или в папку загрузок, если путь не указан. Допускаются абсолютные пути
  в другие каталоги ПК и пути относительно стартовой папки.
- **С подтверждением / Правки файлов / План:** локальное действие показывает
  отдельный запрос; место сохранения файла выбирается через системный диалог.

Claude получает два настоящих MCP-инструмента. Дополнительная инструкция сообщает
ОС, каталог запуска и режим; выполнение делает код Relay через существующее SSH-
соединение. У модели нет прямого соединения с ПК или отдельного пароля от него.

Скачивание — до 512 МБ, частями по SSH, со сверкой размера и SHA-256. До окончания
проверки файл хранится отдельно. При замене прежний обычный файл сохраняется рядом
под скрытым именем `.relay-backup-*`; каталоги и специальные файлы не заменяются.
Windows использует PowerShell, Linux — `/bin/sh`. Claude получает stdout, stderr и
код завершения; до 120 секунд на команду, 16 КиБ вывода на каждый поток с отметкой
о сокращении. Фоновая программа может продолжить работу после команды запуска.

Остановка задачи отменяет ожидающие локальные действия и активную команду.
Разрешение Авто проверяется на самом ПК для конкретной беседы; поле `auto` в ответе
сервера само по себе ничего не разрешает. При отключении ПК локальные политики
сбрасываются. Повышение прав пользователя автоматически не выполняется.

Например: «Скачай собранный jar в мой инстанс» или «Проверь локальный latest.log».
Автоматизация Minecraft зависит от установленного лаунчера и средств управления;
Relay не содержит готового игрового бота и не запускает игру самостоятельно.

На сервере создаётся временный MCP-помощник и приватный Unix-сокет в каталоге 0700.
Они работают в рамках SSH-подключения, без новых TCP-портов и постоянного сервиса.
Используется [MCP в Claude Code](https://code.claude.com/docs/en/mcp).

## Журнал действий

Последовательные чтения, команды и их результаты свёрнуты в строку вида
**12 действий · Показать**. В журнале остаются короткие названия файлов; полные
параметры и результаты открываются при выборе действия. Ошибки видны в свёрнутом
заголовке. Текст разговора, вопросы и запросы разрешений остаются на виду.

## Режимы работы

- **Авто:** встроенный автоматический режим Claude Code, без отключения системы разрешений. Выбран по умолчанию; последняя настройка сохраняется для сервера.
- **С подтверждением:** запросы разрешений Claude появляются в чате с кнопками.
- **Правки без запроса:** обычные изменения файлов разрешены; остальные запросы
  Claude по-прежнему показываются.
- **Планирование:** Claude изучает задачу и готовит план.

**Effort**: авто, low, medium, high, xhigh и max. Настройка сохраняется для сервера;
доступность уровней зависит от модели и версии Claude Code.

Изменение режима, модели или Effort применяется при следующем сообщении. Поддерживаются
модель сервера по умолчанию, Sonnet и Opus. **Стоп** прерывает текущий ответ.
Вопросы Claude поддерживают варианты, несколько вариантов и свободный ответ.
Relay не добавляет `--dangerously-skip-permissions`.

## Лимиты Claude

В нижней части панели сервера показаны шкалы использования за **5 часов** и
**неделю**, проценты и время до сброса. Данные обновляются при подключении,
затем не чаще раза в минуту и по событиям Claude Code. На сервере используется
уже имеющаяся действующая авторизация подписки. Серверный помощник читает OAuth-
токен из конфигурации Claude для запроса статистики; на ПК токен не передаётся.

Дополнительный источник лимитов — фиксированный endpoint самого Claude Code.
Его HTTP-контракт не является публичным и может меняться. При недоступности
используются официальные события `rate_limit_event`; если и они не содержат
проценты, интерфейс явно показывает отсутствие данных, без расчётов по числу токенов.
Relay не обновляет авторизацию и не запускает задачу Claude для проверки лимитов.

## Данные и пароли

Профили: `%APPDATA%\relay-desktop\settings.json` на Windows,
`$XDG_CONFIG_HOME/relay-desktop/settings.json` или `~/.config/relay-desktop/settings.json`
на Linux. В JSON нет паролей или локальных копий разговоров.

По флажку **Запомнить пароль** используется Windows Credential Manager или
Secret Service на Linux (GNOME Keyring, KeePassXC с Secret Service и т. п.).
Если хранилище недоступно, Relay сообщает об этом и позволяет подключиться без
записи пароля на диск. Пароли не кладутся в командную строку или журнал приложения.
Приложение не собирает телеметрию.

## Сборка и проверки

Исходники — Rust 1.98, egui/eframe, russh, Python stdlib для серверного помощника.
На Windows для сборки нужны Rust MSVC и Microsoft C++ Build Tools.
На Linux — Rust, C-компилятор, pkg-config и заголовки libdbus-1.

```sh
cargo build --release --locked
cargo test --locked
cargo test --locked -p egui_commonmark --lib relay_list_layout_tests
python3 -m unittest discover -s tests -v
python3 tools/package.py
```

`tools/build-windows-local.sh` — дополнительный вариант кросс-сборки с Linux:
требует подготовленных официальных Rust и llvm-mingw внутри `.tools/`.
Обычная сборка на Windows не требует этих скриптов. Workflow в `.github/workflows/`
собирает обе платформы на собственных runner-ах без публикации релиза.

Названия сессий берутся из содержательных сообщений. Строки `--resume`, `/resume`
и другие служебные команды не используются в заголовках. Оригинальные сессии не удаляются.

`relay --demo` — автономный предпросмотр с вымышленными данными. К реальным
серверам он не подключается. `--screenshot <path>` сохраняет только окно Relay.

Протокол и флаги сверены с [документацией Claude Code](https://code.claude.com/docs/en/cli-reference)
и [официальным Agent SDK](https://github.com/anthropics/claude-agent-sdk-python).
Это независимое приложение, не официальный продукт Anthropic.

## Проверка интерфейса

`python3 tools/preview.py` сохраняет реальные снимки чата, подключения, пустого чата
и светлой темы. `tools/check-paste.py` проверяет фактический Ctrl+V в отдельном
демоокне с восстановлением буфера; не затрагивает рабочие сессии.
Шрифт Inter распространяется по OFL, лицензия — `assets/Inter-LICENSE.txt`.
Локальные изменения `vendor/egui_commonmark` и `vendor/egui_commonmark_backend`
исправляют выравнивание списков и интервалы в тексте.
`vendor/egui-winit` содержит небольшой фикс передачи события Ctrl+V: стандартная
интеграция перехватывала его даже при отсутствии текста в буфере.
